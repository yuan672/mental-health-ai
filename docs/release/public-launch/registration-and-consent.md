# 注册与正式授权：最小接入方案

2026-09-18，待审实施方案。目标为安徽个人运营的免费成人网站。当前缺少年龄服务商、公开联系邮箱、域名及正式审核过的政策文件；本文件不表示已经接通生产注册。

## 已有能力直接复用

- Email/密码登录、Cookie Session、Origin/CSRF、Argon2、限流、原子注册事务。
- `AgeVerificationProvider` 的 `verify({ candidateUserId, evidenceToken })` 接口，以及只保存成年结果、方法、时间的最小字段。
- Consent Registry 的精确文档身份、不可变 decision、revision、精确 replay、撤回协调。

生产注册在 `registration-requirements.service.ts` 仍被限定为 Development/Test + mock；配置仅有 `mock` 和 `unconfigured`。提供者没有确定前保持此拒绝行为，不把成年勾选、邮箱或普通实名认证本身当作已核验成年。

## 注册需要补的实际工作

1. 选择允许个人主体用于本服务的成年验证服务商，取得其真实接口/鉴权、结果字段、数据地点与留存说明。优先只让本站接收成年判定，避免本站保存身份证图片和原始号码。
2. 明确证据和待注册主体如何绑定、有效期与重放规则。现在 `candidateUserId` 是注册请求内新建的 UUID；不能直接声称提前拿到的 token 已绑定该 UUID。如果厂商需要回调、跳转或预注册状态，按 ADR-011 第三节新增窄幅设计后实施。
3. 通过已有 provider port 接入；只在 provider 配置真实、政策文档合格时开放注册。失败、未成年、过期凭证均不得落半套账户。
4. 当前邮箱尚无真实性验证或找回流程。公开注册前选定受控邮箱验证/找回方式；没有邮件服务商时不自造已验证标志，也不把输入邮箱当作可靠身份恢复凭据。

提供商未知时编写一个任意 HTTP endpoint 适配器没有实际接入价值，本轮不这样做。

## 授权按功能区分

以下是待批准的最小产品/工程选择，不是已经实施的三种新 Consent：

| 决定                   | 何时征求                                    | 拒绝/撤回的影响                                                        |
| ---------------------- | ------------------------------------------- | ---------------------------------------------------------------------- |
| 服务协议、基础隐私告知 | 注册前，文件可在登录前阅读                  | 无有效账号条件时不注册；文档告知不自动等于全部处理同意                 |
| 私人敏感记录处理       | 首次使用需要保存此类内容的日记/心情等功能前 | 阻止新的相关内容处理；保留权利请求、查看/删除与注销通道，不自动打开 AI |
| 第三方 AI 处理         | 首次 AI 请求前，与接收方/目的/数据种类绑定  | 拒绝后仍可使用已获相应授权的非 AI 功能；撤回终止依赖该授权的执行       |
| 可选日记参考           | AI 处理同意有效后，再选择日记本范围         | 默认关闭；仅缩小/开放日记上下文；单次跳过优先，不能扩大授权            |

现有 Terms/Privacy 固定两项、注册 required set 和 AI required set 共用，不能直接多塞一个注册必选框。需要将 **账号准入**、**功能处理资格** 与 **日记访问范围** 区分，并让 snapshot/recheck 使用对应的授权依赖。日记现有 scope/revision 不是 document-bound 的法律同意证明。

对当前敏感信息处理的合法基础、第三方究竟是受托处理还是独立接收者，需按真实合同确认；不能把笼统勾选替代具体告知或必要的单独同意。

## 文档发布方式

使用[候选正文](policy-drafts.md)完成运营者、公开联系、真实 Provider、保存删除规则后再审核。正式版采用新的 version/key/revision，不能覆盖已使用的 synthetic `1.1/test-revision-2`。未审核保持 `draft`；`production_reviewed` 只记录实际审批结果。首次生产发布不继承测试用户的合成接受记录。

增加公开、版本化、无需登录即可读的正式文档，并让 Registry 与实际正文身份一致。修改关键处理目的或接收方时发布新身份并重新征求必要同意，不静默换正文。

## 仅验证新增边界

真实 provider 接通时验证一次有效成年凭证、无效/未成年/过期拒绝及原子失败；新增授权只覆盖非 AI 可用、未授权不外发、撤回和旧文档拒绝。沿用现有已通过的账号/Consent 测试，不为此重跑 NF-04、全量模型对话或全面视觉验收。

## 需要正式记录的决策

实现前以新 ADR 窄幅细化/替代 ADR-011 的真实注册流程与 ADR-016 的固定两类要求，不修改 Accepted 历史。这不是新增项目阶段，而是当前四项上线补齐中必须明确的契约。

依据：[个人信息保护法](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)第 17、21、23、28–30 条，分别涉及告知、受托处理、对外提供和敏感信息处理；具体适用随真实服务关系确认。
