# 私人日记与 AI 聊天联动：实现与验证

日期：2026-09-15。依据用户审核方案及“现在去实现吧”的授权，实现 ADR-026。

## 已接入

- 书架及普通聊天页提供“AI 日记读取权限”：完全不允许、指定日记本、全部日记本。
- 默认关闭。指定模式不自动加入新书；全部模式包括新书。设置明确保存、刷新后保留，并检查修改版本。
- 普通聊天读取本人获准日记本最近 7 个上海自然日内已保存的文字、标题、心情、天气，最多提供 5 篇有限片段。
- 无痕聊天、临时勾选“这次不参考日记”、高风险与安全兜底分支不检索日记。草稿、照片不作为日记上下文外发。
- 真正发送前复查权限、所属账号、日期和内容哈希；变化时停止发送并提示重新发送。
- 最新一轮显示“本次提供给 AI 的日记”及日期、标题、原文链接；修改或删除后显示不可用，不保留原文副本。
- 不建立第三方向量库，不保存额外日记摘要。已有聊天回复可能提及旧日记，关闭权限不会删除聊天记录或撤回已发送给服务商的内容。

## 本地真实模型验证

所有账号和内容均为新建合成测试数据，未读取、复制或发送用户真实日记。
使用当前硅基流动模型和完整真实安全检查，没有放宽安全阈值或替换结果。

最终 HTTP 联调 23 项通过：注册/登录、默认关闭、创建合成日记、另存未公开草稿、
指定授权、真实 SSE 回复、日记来源、已保存聊天、额度增量、全开放/关闭及清理。
模型准确回答合成日记中浅绿色陶艺作品叫“青豆杯”，没有输出草稿独有的标记。
来源接口返回正确的日记本、日期与版本；一轮成功对话消耗一次额度。

首次 HTTP 尝试触发既有输出安全拦截，返回安全替代文本。该次未保存原始候选回复，
不能据此断言是误判。随后使用独立应用实例记录同一合成场景的安全检查结果，5 次
输出检查均批准且完整编排成功；再用原 HTTP 场景复测成功。期间没有修改安全检查。
因此这证明联动链路可用，不表示真实模型每次都会给出相同回复或从不触发兜底。

本地忽略目录的证据：`test-results/diary-memory-live-attempt-1.json`、
`diary-memory-diagnostic-report.json`、`diary-memory-live-report.json`。
合成日记本和聊天已经删除，合成账号读取权限关闭并登出；没有删除用户原有内容。

## 人工验收

前端：<http://localhost:5173/app/diary>；聊天：<http://localhost:5173/app/chat>。

1. 在书架打开权限设置，选择指定日记本并保存，刷新后确认选择保留。
2. 在获准日记本保存最近一周的一段文字，到新聊天询问这段经历。
3. 检查“本次提供给 AI 的日记”的展开内容及原文链接。
4. 勾选“这次不参考日记”发送，再切换为完全不允许并新建聊天。
5. 检查弹窗布局、手机适配及配色；书本开合、翻页和小猫动效保持原有实现。

没有执行 Computer Use、浏览器自动化、截图或 UI 视觉验收；界面验收由用户完成。
工程及局部真实模型联调不构成生产安全评估或临床验证。
